# AI 变更检查清单

## 开始前

- [ ] 明确请求是诊断、文档更新还是代码实现。
- [ ] 读取 `AGENTS.md`、项目上下文和相关 canonical guide。
- [ ] 用 `rg` 找到真实入口、调用方、配置键、路由和测试。
- [ ] 确认当前 worktree 的已有修改，不覆盖无关变更。

## 设计时

- [ ] 写清当前行为、根因、影响范围和正确修改层。
- [ ] 说明是否影响缓存、刷新、事务、权限、并发、关闭或外部依赖。
- [ ] 只有真实变化点存在时才引入 interface 或设计模式。
- [ ] 明确数据真相源，避免从 UI、token 或缓存推导安全结论。

## 实现时

- [ ] handler、service、model、provider 边界没有混淆。
- [ ] 空值、错误、超时、取消和资源关闭路径明确。
- [ ] 配置、路由、权限目录和 OpenAPI 同步更新。
- [ ] 文档命令、端口、路径和配置键与当前代码一致。
- [ ] 不把密码、token、DSN 或固定 secret 写入示例和日志。

## 验证时

- [ ] 先跑受影响包测试。
- [ ] 跨模块修改跑 `make test`、`go test -race ./...`、`go vet ./...`。
- [ ] 后端构建跑 `make build`；前端修改跑 typecheck/build。
- [ ] 路由/权限/OpenAPI 修改跑 contract tests。
- [ ] 文档修改运行 `make docs.check` 和 `git diff --check`；必要时再用 `rg` 检查旧命令和旧路径。

## 交付时

- [ ] 说明实际运行过的命令及结果。
- [ ] 说明未运行的检查和原因。
- [ ] 区分本地代码完成、部署就绪和外部服务可用。
- [ ] 更新对应的计划、审计或 canonical guide。
