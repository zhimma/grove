# 响应、错误与请求校验

HTTP handler 使用 `pkg/validation` 绑定请求，通过 `pkg/response` 输出；service 返回数据与 `error`。协议实现分别见 `pkg/response/response.go`、`pkg/errx/errors.go` 和 `pkg/validation/request.go`。

## 响应协议

成功响应：

```json
{"code": 0, "message": "ok", "data": {}, "request_id": "req_xxx"}
```

失败响应：

```json
{
  "code": -1,
  "message": "请求参数校验失败",
  "data": {
    "error_code": "invalid_params",
    "errors": {"email": ["邮箱格式不正确"]}
  },
  "request_id": "req_xxx"
}
```

`message` 用于展示，HTTP 状态码与 `data.error_code` 用于流程判断。列表数据统一为 `data.list` 和 `data.meta`，其中 `meta` 使用 `total`、`page`、`page_size` 和 `total_pages`；前端共用 `types/pagination.ts`。

`request_id` 由请求中间件提供，同时返回 `X-Request-Id`。`data` 为空时可能省略；204 响应不携带 JSON 响应体。

## 四个输出函数

| 调用 | HTTP 状态 | 行为 |
| --- | --- | --- |
| `response.Success(c, data)` | 200 | 标准成功响应 |
| `response.Created(c, data)` | 201 | 标准创建响应 |
| `response.NoContent(c)` | 204 | 空响应，保留请求 ID 响应头 |
| `response.Fail(c, err)` | 由错误决定 | 归一化错误、记录必要日志并输出失败响应 |

`Fail` 只接收 `error`，`nil` 不输出响应。Handler 遇到错误后应立即返回：

```go
if err != nil {
    response.Fail(c, err)
    return
}
response.Success(c, result)
```

不要在 handler 中自行拼另一套 JSON 错误结构。

## 错误构造与状态码

```go
return nil, errx.Conflict().
    WithCode("role_code_exists").
    WithMessage("角色编码已存在")
```

| 状态 | 常见用途 |
| --- | --- |
| 400 | JSON、Query 或 URI 无法正确绑定 |
| 401 | 缺少或无效凭据、登录失效 |
| 403 | 身份有效但权限不足、账号或角色不可用 |
| 404 | 资源不存在 |
| 409 | 唯一性冲突或当前状态不允许操作 |
| 413 | 请求体或上传文件超过限制 |
| 422 | validator、请求 `Validate()` 或显式业务语义校验失败 |
| 429 | 登录限流等频率限制 |
| 500 | 未预期的内部错误 |
| 503 | 必需依赖或服务未配置、不可用 |

`InvalidParams()` 默认 400；语义校验可显式使用 `WithHTTPStatus(422)`。具体接口以 OpenAPI 和 handler 为准，不依赖文案推断错误类型。

底层错误通过 `WithCause(err)` 保留，可用 `errors.As` 和 `errors.Is` 检查标准 Go 错误链。`With*` 返回副本，业务不共享可变的错误实例。自定义错误没有错误码时，响应层根据 HTTP 状态补齐稳定的错误码。

内部错误对外使用通用提示。只有 `app.debug=true`、HTTP 状态为 5xx 且存在底层错误时，响应才包含 `data.debug.error` 和 `data.debug.type`。panic 堆栈只写日志，不返回客户端。

## 参数绑定

```go
type CreateRoleRequest struct {
    Name string `json:"name" binding:"required,max=64" label:"角色名称"`
}

var req CreateRoleRequest
if err := validation.BindJSONStrict(c, &req); err != nil {
    response.Fail(c, err)
    return
}
```

- 新增公开 JSON API 优先使用 `BindJSONStrict`，拒绝未知字段和连续的多个 JSON 值。
- `BindJSON` 和 `BindJSONAllowUnknown` 保留兼容性的未知字段处理；现有 Console handler 和生成器使用 `BindJSON`。两种方式都只接受一个 JSON 文档。
- Query 和 URI 分别使用 `BindQuery`、`BindURI`；绑定成功后执行 validator 和请求类型的 `Validate() error` 钩子。
- 字段中文名来自 `label`；字段错误归入 `data.errors`。
- PATCH 请求或可选字段更新使用指针区分“未传”和“传零值”。不要给允许 `0` 或 `false` 的字段直接套 validator 的 `required`。

校验失败后不进入 service，数据唯一性、状态流转等业务规则由 service 和数据库约束共同保证。

## 前端处理

请求入口是 `web/admin-vben/apps/console/src/api/request.ts`；`utils/http-error.ts` 解析 `status`、`message`、`errorCode`、`fieldErrors` 和 `requestId`。

401 走刷新或登录失效流程，422 的字段错误供页面回填，其余错误按接口文案提示。敏感信息不应放进 `message` 或字段错误；服务端底层错误不作为业务控制信号。

新增接口同时更新 [OpenAPI 与前端契约](03-console-新增模块指南.md)，并运行 `make contracts admin.contract`。
