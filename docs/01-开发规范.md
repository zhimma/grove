# 开发规范

> 本文档是 `grove` 项目的统一代码约定,所有 Go 后端模块(API、Console、Worker)都按此执行。
> 目标:像 Laravel 一样快速搭起一个新接口,但不引入 Repository、DDD、DTO/VO 等额外抽象;所有公共能力(响应、错误、校验、ID、时间、事务、日志、权限、中间件)都已收口到 `pkg/*` 和 `internal/*`,业务代码按模板写即可。

## 2. 命名规范

### 2.1 文件

| 类型 | 规范 | 示例 |
|---|---|---|
| 文件 | snake_case | `user_handler.go`, `order_service.go` |
| 测试文件 | `_test.go` | `user_service_test.go` |
| 模型文件 | 复数小写 | `console_admins.go`(对应 `ConsoleAdmin`) |

### 2.2 代码

| 类型 | 规范 | 示例 |
|---|---|---|
| 结构体 | PascalCase | `User`, `OrderItem` |
| 接口 | PascalCase + 能力后缀 | `Repo`, `Manager`, `Resolver` |
| 函数/方法 | PascalCase | `GetUser`, `CreateOrder` |
| 变量 | camelCase | `userID`, `orderList` |
| 常量 | UPPER_SNAKE | `MAX_RETRY`, `DEFAULT_TIMEOUT` |
| 包名 | 全小写 | `auth`, `database`, `response` |
| 错误码 | snake_case | `account_exists`, `role_code_exists` |
| JSON 字段 | snake_case | `display_name`, `last_login_at` |

### 2.3 路由命名(用于权限 UI 展示)

```text
{模块}.{操作}
```

```go
roles.GET("", h.List).Name("角色权限.角色列表")
roles.GET("/:id", h.Detail).Name("角色权限.角色详情")
```

> `.Name()` 只影响展示,不影响鉴权;真正鉴权认 `METHOD + path`。

## 3. 禁止事项(红线)

```go
// ❌ 禁止 Java/DDD 风格抽象
// 不要 Repository Pattern
// 不要 DTO / VO / Assembler
// 不要 Domain Service / Aggregate
// 不要 CQRS / Event Sourcing

// ❌ 禁止隐式全局依赖
db := global.DB   // 不要这样

// ❌ 禁止 handler 直接持有数据库连接
type UserHandler struct {
    db *gorm.DB
}

// ❌ 禁止 handler 直接调用 model 查询
func (h *UserHandler) Get(c *gin.Context) {
    user, _ := model.FindUser(c, h.db, c.Param("id"))
}

// ❌ 禁止在请求处理函数内部 new service
func (h *UserHandler) Create(c *gin.Context) {
    userSvc := service.NewUserService(db)  // 应在 RegisterXxxRoutes 阶段装配
}

// ❌ 禁止直接把 service 结构体当 HTTP 入参
var req service.CreateUserInput
c.ShouldBindJSON(&req)  // 改用 handler 内的 CreateUserRequest

// ❌ 禁止 HTTP 200 包装失败
c.JSON(200, gin.H{"code": -1, "message": "失败"})  // 用 response.Fail + errx

// ❌ 禁止 gin.H / interface{} 作为响应数据
type Response struct {
    Data interface{} `json:"data"`  // 必须用具体类型
}
```

**项目专属红线**:

- service **禁止** `import "internal/provider"`,只接收显式依赖(`dbRepo`、`enforcer`、`txManager` 等)。
- model **禁止**返回 `*errx.HTTPError` 之外的业务错误、不组装 HTTP 响应。
- handler **禁止**用 `c.JSON` / `c.AbortWithStatusJSON`,统一 `response.Success` / `response.Fail`。
- 业务代码 **禁止**使用标准库 `log`,统一 `pkg/logger`。
- 业务代码 **禁止**直接 `fmt.Print*`(CLI 除外)。
- handler **禁止**抛 panic;由 `internal/middleware/recovery.go` 收口。

## 4. 分层与职责

项目统一采用 `handler + service + model` 三层,**不引入 `repo` 层**(数据访问放 `model` 的可复用查询里)。

### 4.1 Handler

只做 HTTP 相关工作:

- 参数绑定(`validation.BindJSON/Query/URI`)
- 从 `request.Identity` 读取身份信息
- 调用 service
- 输出 `response.Success` / `response.Fail`

**约束**:

- 不直接持有 `db`
- 不直接调用 `model` 查询
- 不编排业务逻辑
- 自己定义 HTTP `Request/Response` 结构体(与 handler 同文件、同包)
- 字段映射直接写在 handler 内,不抽 `toXxxDetail` 辅助函数

### 4.2 Service

负责业务逻辑:

- 权限判断、事务控制、数据聚合
- 持 `dbRepo`(或具体 `*gorm.DB`)、`enforcer`、`txManager` 等基础依赖
- 只接收 `context.Context`
- 使用 `Input/Output` 结构体
- 业务错误统一 `pkg/errx`

**约束**:

- 不接收 `*gin.Context`
- 不返回 HTTP 响应对象
- **不** `import "internal/provider"`(只能拿显式依赖)
- 复用超过 2 处的查询放到 `model`,不在 service 里复制粘贴

### 4.3 Model

放模型定义和可复用查询:

- GORM 模型定义
- 复用超过 2 处的查询(`FindUserByID` 这类)抽到这里

**约束**:

- 不做权限判断
- 不做业务编排
- 不组装 HTTP 响应
- 不抛 `*errx.HTTPError` 之外的业务错误

### 4.4 Router 装配

```go
// 推荐风格:在 RegisterXxxRoutes 阶段完成所有依赖装配
func RegisterUserRoutes(public *gin.RouterGroup, p *provider.Provider) {
    h := &UserHandler{
        userSvc: service.NewUserService(p.DB),
    }
    users := route.Wrap(public.Group("/users"))
    users.GET("/:id", h.Get)
}
```

> 根目录规范里 `newXxxHandler(p)` 的工厂写法是更细的可选模式;本项目当前用 `RegisterXxxRoutes` 一把装配,二选一,保持一致即可。

## 5. Handler:参数绑定 / Request / Response

### 5.1 三种绑定方式

| 场景 | 函数 | tag |
|---|---|---|
| `POST` / `PUT` Body | `validation.BindJSON(c, &req)` | `json:"xxx"` |
| `GET` 列表 / 过滤 | `validation.BindQuery(c, &req)` | `form:"xxx"` |
| 路径参数 | `validation.BindURI(c, &req)` | `uri:"xxx"` |

绑定失败统一交给 `response.Fail(c, err)`,**不要**自己解 `err`。

### 5.2 Request 结构体规范

- 与 handler 同文件、同包。
- 字段顺序:必填在前,可选在后。
- `binding` 规则 + `label` 中文名同时存在:

```go
type CreateUserRequest struct {
    Name   string `json:"name"    binding:"required"          label:"姓名"`
    Email  string `json:"email"   binding:"required,email"    label:"邮箱"`
    RoleID string `json:"role_id" binding:"required"          label:"角色"`
}
```

可选更新用指针 + `omitempty`(避免 "传 0 也会被更新" 的坑):

```go
type UpdateUserRequest struct {
    Name   *string `json:"name"   binding:"omitempty,max=120" label:"姓名"`
    Status *int    `json:"status" binding:"omitempty,oneof=0 1" label:"状态"`
}
```

> 历史拼写 `lebel` 不再兼容,新代码**只**用 `label`。

### 5.3 自定义 `Validate() error`

Request 结构如果实现了 `Validate() error` 方法,`validation.Bind*` 在 tag 校验通过后**自动**调用。失败统一回 `422` + `data.errors._error`:

```go
type TransferRequest struct {
    From   string `json:"from"   binding:"required" label:"转出方"`
    To     string `json:"to"     binding:"required" label:"转入方"`
    Amount int64  `json:"amount" binding:"required,gt=0" label:"金额"`
}

func (r *TransferRequest) Validate() error {
    if r.From == r.To {
        return errors.New("转出方与转入方不能相同")
    }
    return nil
}
```

### 5.4 Body 可空(登出类)

Body 可能为空(登出、退出),需手动判断,避免 `EOF` 直接报错:

```go
var req LogoutRequest
if c.Request.ContentLength > 0 {
    if err := validation.BindJSON(c, &req); err != nil {
        response.Fail(c, err)
        return
    }
}
```

### 5.5 Response 结构体规范

- 与 Request 同文件、同包。
- 字段类型用业务语义类型,**不用** `interface{}` / `gin.H`。
- 时间字段在**这一层**就转成 `string`,不进 `time.Time`。
- 分页响应统一:

```go
type ListResponse struct {
    List []Item `json:"list"`
    Meta ListMeta `json:"meta"`
}

type ListMeta struct {
    Total      int64 `json:"total"`
    Page       int   `json:"page"`
    PageSize   int   `json:"page_size"`
    TotalPages int   `json:"total_pages"`
}
```

## 6. Service:Input / Output / 事务 / 错误

### 6.1 标准方法签名

```go
type XxxService struct { /* 依赖 */ }

type DoXxxInput  struct { /* 业务参数 */ }
type DoXxxOutput struct { /* 业务返回 */ }

func NewXxxService(deps ...) *XxxService { ... }

func (s *XxxService) DoXxx(ctx context.Context, in DoXxxInput) (DoXxxOutput, error) { ... }
```

**强约束**:

- 第一个参数永远是 `context.Context`,命名固定 `ctx`。
- 命名:基本查询 → `GetXxx` / `ListXxx`;变更 → `CreateXxx` / `UpdateXxx` / `DeleteXxx`;动作 → `Xxx`(动词)。
- Output 字段全部导出,大写驼峰;序列化直接复用 `json:"snake_case"` 标签,service 不再二次映射。

### 6.2 多表写入 → 事务

需要事务的 service 暴露 `WithTransaction(manager transaction.Manager) *XxxService`,在路由注册时注入:

```go
roleSvc := consoleservice.NewRoleService(p.DB, p.GetEnforcer("console"), runtimeCatalog).
    WithTransaction(p.TxManager)
```

事务内取 db:

```go
return s.txManager.Execute(ctx, func(ctx context.Context) error {
    db := transaction.GetDB(ctx, s.dbRepo.Default())
    return db.WithContext(ctx).Create(&m).Error
})
```

> 事务内**不要**直接用 `s.dbRepo.Default()`,否则会拿到事务外连接;统一 `transaction.GetDB(ctx, s.dbRepo.Default())`。

### 6.3 唯一性 / 冲突类错误

唯一索引冲突的业务码**必须**稳定,前端按 code 提示:

```go
return errx.Conflict().WithCode("account_exists").WithMessage("账号已存在")
```

常见 code 见 §8.3。

## 7. 统一响应(`pkg/response`)

### 7.1 出口

```go
response.Success(c, data)            // 200, code=0
response.Success(c, nil)             // 200, data:null(用于无返回的写操作)
response.Fail(c, err)                // HTTP 状态由 errx 决定
```

### 7.2 响应结构

成功:

```json
{ "code": 0, "message": "ok", "data": { ... }, "request_id": "req_xxx" }
```

失败(无字段错):

```json
{
  "code": -1,
  "message": "角色编码已存在",
  "data": { "error_code": "role_code_exists" },
  "request_id": "req_xxx"
}
```

失败(字段错):

```json
{
  "code": -1,
  "message": "请求参数校验失败",
  "data": {
    "error_code": "invalid_params",
    "errors": { "code": ["角色编码不能为空"] }
  },
  "request_id": "req_xxx"
}
```

失败(500 + 调试模式):

```json
{
  "code": -1,
  "message": "系统繁忙,请稍后再试",
  "data": {
    "error_code": "internal_error",
    "debug": { "error": "dial tcp ...", "type": "*net.OpError" }
  },
  "request_id": "req_xxx"
}
```

> `data.debug` **仅在** `app.debug=true` 时出现;`request_id` 永远存在。

### 7.3 panic 处理

业务层不写 `recover()`。所有 panic 由 `internal/middleware/recovery.go` 收口,统一 500 + `internal_error`。

## 8. 错误处理(`pkg/errx`)

> 包名是 `pkg/errx`(不是 `pkg/errors`)。调用形式:`errx.NotFound().WithMessage("...")`。

### 8.1 构造器与状态码

| 构造器 | HTTP | 默认错误码 | 默认 message |
|---|---|---|---|
| `errx.InvalidParams()` | 400/422 | `invalid_params` | 请求参数格式不正确 |
| `errx.Unauthorized()` | 401 | `unauthorized` | 未登录或登录已失效 |
| `errx.Forbidden()` | 403 | `forbidden` | 无权限访问 |
| `errx.NotFound()` | 404 | `not_found` | 资源不存在 |
| `errx.Conflict()` | 409 | `conflict` | 数据冲突 |
| `errx.TooManyRequests()` | 429 | `too_many_requests` | 请求过于频繁 |
| `errx.Internal()` | 500 | `internal_error` | 系统繁忙,请稍后再试 |
| `errx.ServiceUnavailable()` | 503 | `service_unavailable` | 服务暂不可用 |

### 8.2 链式 API

```go
errx.NotFound().WithCode("user_not_found").WithMessage("用户不存在")
errx.Internal().WithCause(err)                                       // 原始 error 写入日志 / 调试
errx.InvalidParams().WithHTTPStatus(422).WithMessage("账号和密码不能为空")
errx.Forbidden().WithMessage(fmt.Sprintf("无权限访问: %s", perm))
```

底层 error 携带统一用 `WithCause`,**不要** `fmt.Errorf("...: %w", err)` 再返回——响应层识别不到。

### 8.3 唯一错误码收敛

| 业务 | error_code |
|---|---|
| 登录态失效 | `unauthorized` / `invalid_credentials` |
| 账号禁用 | `account_disabled` |
| 角色不可用 | `role_unavailable` |
| 刷新令牌无效 | `invalid_refresh_token` |
| 唯一冲突-账号 | `account_exists` |
| 唯一冲突-邮箱 | `email_exists` |
| 唯一冲突-手机 | `phone_exists` |
| 唯一冲突-角色编码 | `role_code_exists` |
| 系统配置冲突 | `config_key_exists` |
| 内部 DB 异常 | `database_error` |

> 新增业务错误时,先把 `code` 加到本表,**再**写代码。

## 9. 通用请求约定

### 9.1 分页

| 字段 | 默认 | 限制 | tag |
|---|---|---|---|
| `page` | 1 | `min=1` | `form:"page" binding:"omitempty,min=1"` |
| `page_size` | 20 | `min=1,max=100` | `form:"page_size" binding:"omitempty,min=1,max=100"` |
| `offset` | - | - | 配合 `limit` 用,二选一 |
| `limit` | - | - | - |
| `list_all` | false | - | 列表导出时使用 |

service 层统一 `resolvePage(input ListRequest) (page, pageSize int)`,见 `app/console/internal/service/common.go`。

### 9.2 排序

- 字段名 `order_by`(`form`);支持多列用 `[]string`。
- 前缀 `-` = DESC,`+` 或无前缀 = ASC。
- 字段名一律**小写 snake_case**,service 层用 `parseOrderBy("")` 解析。

```go
type ListRolesRequest struct {
    OrderBy []string `form:"order_by" label:"排序字段"`
}
// 调用: GET /roles?order_by=-created_at&order_by=name
```

### 9.3 状态过滤

- 状态字段用 `*int`(指针 + `omitempty`)。`nil` = 不过滤。

```go
Status *int `form:"status" label:"状态"`
```

### 9.4 唯一性 / 冲突错误码

见 §8.3。前端按 `data.error_code` 判断业务冲突类型。

## 10. ID 规范(`pkg/ulid`)

### 10.1 规则

- **全部主键使用 ULID**,26 字符、`varchar(26)`、字典序近似时间序。
- 创建时由 `Base.BeforeCreate` 自动注入,业务代码**不**手动生成:

```go
type Base struct {
    ID        string     `gorm:"primaryKey;type:varchar(26)" json:"id"`
    CreatedAt time.Time  `json:"created_at"`
    UpdatedAt time.Time  `json:"updated_at"`
    DeletedAt *time.Time `gorm:"index" json:"deleted_at,omitempty"`
}

func (b *Base) BeforeCreate(tx *gorm.DB) error {
    if b.ID == "" {
        b.ID = ulid.New()    // pkg/ulid 包装,不要直接 ulid.Make()
    }
    return nil
}
```

### 10.2 为什么用 ULID

- 时间排序,索引友好
- 26 字符,比 UUID 短
- 字典序即时间序

### 10.3 字段宽度

| 关联类型 | 字段长度 |
|---|---|
| 主键 ID | `size:26` 或 `varchar(26)` |
| 外键引用 | `size:26;index` |
| 资源 ID 在日志 / 审计 | `size:64`,预留可读编码 |

### 10.4 JSON 输出

`id` 始终以字符串形式输出(ULID 是 26 位 base32,不会丢精度)。**不允许**用数字类型。

## 11. 时间规范

### 11.1 字段类型

| 业务语义 | Go 类型 | JSON 输出 |
|---|---|---|
| 必填时间(创建/更新) | `time.Time` | `2006-01-02 15:04:05` |
| 可空时间(删除/最后登录/最后操作) | `*time.Time` + `omitempty` | 同上,无值时不输出 |

### 11.2 API 输出的时间格式

统一 `2006-01-02 15:04:05`(本地时区),由 service 层的 `formatTime(t time.Time) string` 完成:

```go
func formatTime(t time.Time) string {
    return t.Format("2006-01-02 15:04:05")
}
```

**不允许**把 `time.Time` 直接 `json` 输出,前端不要看 RFC3339 字符串。

### 11.3 入参时间解析

`service/common.go` 提供 `parseTime(s string, endOfDay bool) (time.Time, error)`,支持三种格式:

- `2006-01-02T15:04:05Z07:00`(RFC3339)
- `2006-01-02 15:04:05`
- `2006-01-02`(纯日期,`endOfDay=true` 时回退到当天 23:59:59)

> Request 结构体里**不要**直接用 `time.Time` 绑字段;统一先接 `string`,再在 service 里 `parseTime`。

### 11.4 时间范围查询

分页 + 时间范围是高频组合,字段命名统一:

| 字段 | 含义 |
|---|---|
| `created_from` | 创建时间起(含) |
| `created_to` | 创建时间止(含) |
| `updated_from` / `updated_to` | 同上 |
| `login_from` / `login_to` | 登录时间窗 |

### 11.5 不要做的

- 不要把时间戳(秒/毫秒)当作主存。
- 不要用 `int64` 表达时间。
- 不要让前端传 `1699999999` 这种数字进来。

## 12. 数据库设计(`internal/model` + `pkg/database`)

### 12.1 通用字段

```go
type Base struct {
    ID        string     `gorm:"primaryKey;type:varchar(26)" json:"id"`
    CreatedAt time.Time  `json:"created_at"`
    UpdatedAt time.Time  `json:"updated_at"`
    DeletedAt *time.Time `gorm:"index" json:"deleted_at,omitempty"`
}
```

**所有业务表必须内嵌 `Base`**,不允许再手写 ID/CreatedAt/UpdatedAt/DeletedAt。

### 12.2 字段 Tag 模板

```go
type ConsoleAdmin struct {
    Base
    Account       string `gorm:"size:120;uniqueIndex;not null" json:"account"`
    Username      string `gorm:"size:120"                     json:"username"`
    Email         string `gorm:"size:160"                     json:"email"`
    Phone         string `gorm:"size:32"                      json:"phone"`
    Password      string `gorm:"size:255;not null"            json:"-"`     // 不外露
    Status        int    `gorm:"not null;default:1"           json:"status"`
    LastLoginAt   *time.Time                                  json:"last_login_at,omitempty"`
    LastLoginIP   string `gorm:"size:64"                      json:"last_login_ip"`
    LoginCount    int    `gorm:"not null;default:0"           json:"login_count"`
    Remark        string `gorm:"size:500"                     json:"remark"`
    Role          *ConsoleRole `gorm:"foreignKey:RoleID"      json:"role,omitempty"`
}
```

要点:

- 字符串必带 `size`;`uniqueIndex` 单列唯一;`index` 普通索引。
- 状态/枚举用 `int` + 常量,不要用 `string`。
- 软敏感字段(`Password`、`Secret`、`Token` 等)JSON 用 `json:"-"` 屏蔽。
- 表名:实现 `TableName() string`,统一蛇形复数(`console_admins`)。

### 12.3 软删除 vs 硬删除

- 默认**软删除**(`gorm.DeletedAt`),保留审计价值。
- 真要硬删,显式 `db.Unscoped().Delete(...)`,并在 service 层加注释说明。

### 12.4 复合索引

```go
gorm:"index:idx_system_configs_group_key,unique;not null"
```

索引名固定 `idx_<table>_<col1>_<col2>` 风格。

### 12.5 自定义类型

放在 `internal/datatype/`,目前 `StringArray`(`jsonb`):

```go
type StringArray []string
// 实现 Scanner / Valuer
```

> 新增自定义类型前先看 `internal/datatype/` 是否能复用。

### 12.6 多数据库资源

- `databases.default`:默认连接(必填)
- `databases.resources.<name>`:命名资源,如 `orders`、`crm`、`analytics`

访问:

```go
db, err := p.DB.Get("orders")
// 或
p.DB.Default() // = Get("default")
```

> 业务层拿到 `*gorm.DB` 后**不要**自己缓存;`Repo` 已经做了池化。

### 12.7 事务边界

- 单 service 方法内,所有写入走 `txManager.Execute(ctx, fn)`。
- 跨 service 调用:用 `transaction.WithDB(ctx, db)` 显式传。
- 跨请求不要持有 `*gorm.DB` 实例。

## 13. 中间件与路由

### 13.1 中间件链(Console)

```text
public     : (无)
authed     : AdminAuthn                                  (token 合法即放行)
protected  : AdminAuthn → AuditOperation → AdminPermission
```

`app/api` 没有 Casbin 鉴权,只需要 `UserAuthSet.Optional() / Required()`。

### 13.2 鉴权中间件

```go
// app/api
auth := middleware.NewUserAuthSet(p.TokenManager)
authed.Use(auth.Required())   // 强制
public  .Use(auth.Optional()) // 可选,下游可从 request.GetUserID 拿

// app/console
authed := v1.Group("")
authed.Use(consolemiddleware.AdminAuthn(p.TokenManager, authStateResolver))
```

### 13.3 权限中间件

```go
protected.Use(
    consolemiddleware.AdminAuthn(p.TokenManager, authStateResolver),
    consolemiddleware.AuditOperation(auditDB),
    consolemiddleware.AdminPermission(p.GetEnforcer("console"), cfg.App.Env),
)
```

超管(`request.IsSuper(c) == true`)自动放行,不走 Casbin。

### 13.4 路由包装器

```go
roles := route.Wrap(protected.Group("/roles"))
roles.GET("", h.List).Name("角色权限.角色列表")
roles.POST("/auth/login", h.Login).Ignore()  // 不进权限目录
```

- `.Name("模块.操作")` 只影响展示,不影响鉴权。
- `.Ignore()` 标记的路由不进 Casbin,适合登录、刷新、登出、查自身信息等"已认证但不要权限点"的接口。

### 13.5 审计日志

`AuditOperation` 自动写 `console_operation_logs`,业务层**不要**自己写操作日志;需要带目标/详情时:

```go
request.SetAuditMeta(c, request.AuditMeta{
    TargetType: "role",
    TargetID:   role.ID,
    Detail:     map[string]any{"code": role.Code},
})
```

`Detail` 在 service 写完、handler 返回前调用,会被序列化进 `console_operation_logs.detail_json`。

### 13.6 身份读取

```go
request.GetUserID(c)     // API
request.GetAdminID(c)    // Console
request.IsSuper(c)       // 是否超管
request.GetIdentity(c)   // 完整身份
```

不要从 `c.Get(...)` 自己拿;统一走 `pkg/request`。**包名是 `request`,不是 `reqctx`(旧写法已废弃)。**

### 13.7 写新中间件的位置

| 范围 | 路径 |
|---|---|
| 全局(API + Console 共享) | `internal/middleware/` |
| 仅 Console | `app/console/internal/middleware/` |
| 仅 API | `app/api/middleware/` |

## 14. JWT / Token

### 14.1 Token 类型

- `access_token`:`Authorization: Bearer <token>`,默认 24h。
- `refresh_token`:刷新用,默认 7 天。
- 撤销:写入内存黑名单 + TTL,`tokenManager.Revoke(token)`。

### 14.2 Claims 字段

```go
type Claims struct {
    UserID    string  // 业务侧用户 ID
    AdminID   string  // 控制台管理员 ID
    UserType  string  // "api" / "console"
    Email     string
    RoleID    string
    IsSuper   bool
    TokenType string  // "access" / "refresh"
    jwt.RegisteredClaims
}
```

注意:**不要把授权态写进 token**(角色、菜单、超管标记),运行时必须回数据库看。

### 14.3 解析失败

- 缺 token / 解析失败 → `401 unauthorized`。
- token 类型不匹配(用 refresh 走 access 校验)→ `401 unauthorized` + `invalid_refresh_token` / `invalid_token`。

### 14.4 签发

- API:`tokenManager.IssueAccessToken(userID)`,`UserType="api"`。
- Console:`tokenManager.GenerateAdminTokenPair(adminID, "console")`。

## 15. 日志(`pkg/logger`)

> 业务代码**禁止**用标准库 `log`。

### 15.1 风格

```go
// Info
logger.Info().
    Str("module", "auth").
    Str("event", "login_succeeded").
    Str("user_id", userID).
    Msg("用户登录成功")

// Warn / Error
logger.Warn().Err(err).Msg("登录日志写入失败")
```

> 当前 API:`logger.Info() / Warn() / Error() ... Msg("中文")`;字段链 `.Str/.Int/.Err`,消息体中文、字段名英文 snake_case。

### 15.2 约束

- 字段名英文 `snake_case`
- 消息可用中文
- 敏感信息(密码、token)不打日志
- 同一错误只在一个边界记录一次
- panic 栈、堆栈敏感信息只入日志,不出现在响应里
- CLI 用 `fmt.Print*` 没问题,运行时不准用

## 16. 依赖注入(`internal/provider`)

### 16.1 字段速查

```go
type Provider struct {
    Config       *config.Config
    DB           database.Repo
    RedisClient  *redis.Client    // 注意:不是 p.Redis
    TokenManager *auth.Manager
    JobClient    *job.Client
    JobServer    *job.Server
    Enforcers    map[string]*rbac.Enforcer
    Storage      *storage.Manager
    TxManager    transaction.Manager
    Cache        *cache.Manager
    HTTPClient   *httpclient.Client
    Event        *event.Dispatcher
    Scheduler    *scheduler.Scheduler
}
```

### 16.2 使用边界(红线)

- `Provider` **只**出现在 `server`、`router`、`handler` 装配边界。
- `service` **禁止** `import "internal/provider"`,只接收显式依赖(`dbRepo`、`enforcer`、`txManager` 等)。
- `model` 同上,不导 provider。

```go
// ✅ 正确:service 接收显式依赖
func NewUserService(dbRepo database.Repo) *UserService

// ❌ 错误:service 接收 Provider
func NewUserService(p *provider.Provider) *UserService
```

  - `422 + data.errors` → 表单字段错误,不弹全局 toast

## 20. 代码审查清单

### 20.1 通用

- [ ] Handler 不持有 `db`
- [ ] Handler 不直接调用 `model` 查询
- [ ] Handler 不在请求函数内 `new` service
- [ ] Handler 用 `validation.BindXxx` 绑定,`response.Success/Fail` 输出
- [ ] Service 不导入 `internal/provider`
- [ ] Service 只接收 `context.Context`(不收 `*gin.Context`)
- [ ] Service 用 `Input/Output` 结构,带中文 `label` 的 Request 留在 handler
- [ ] 不用 `interface{}` / `gin.H` 作为响应数据
- [ ] 不返回 HTTP 200 包裹失败
- [ ] 模型嵌入 `Base`,ID 走 ULID
- [ ] 日志字段用英文 `snake_case`,消息用中文
- [ ] 错误用 `pkg/errx` 构造器,底层 error 走 `WithCause`
- [ ] 唯一冲突类错误带稳定 `error_code`
- [ ] 敏感字段(密码/token)`json:"-"`

### 20.2 数据 / 时间 / 事务

- [ ] 时间输出走 `formatTime`(`2006-01-02 15:04:05`),不允许 `time.Time` 直出
- [ ] 入参时间用 `string` + `parseTime`,不直接绑 `time.Time`
- [ ] 多表写入走 `txManager.Execute`,事务内取 db 用 `transaction.GetDB(ctx, ...)`

### 20.3 中间件 / 权限 / 审计

- [ ] 路由使用 `route.Wrap`,需要权限的进 `protected` 分组
- [ ] 需要带审计元信息时调 `request.SetAuditMeta`
- [ ] 身份读取统一 `request.GetUserID/GetAdminID/IsSuper`
- [ ] `.Ignore()` 仅用于"已认证但不要权限点"的接口

### 20.4 新接口自检(9 步)

1. 路由:`route.Wrap(group).METHOD(path, handler).Name("模块.操作")`;无需权限加 `.Ignore()`。
2. Request:每个字段都有 `label`;更新用 `*T`;跨字段校验加 `Validate() error`。
3. handler:绑定 → 调 service → 输出,不要自己捕获 `err`。
4. service:`Input` / `Output` 结构;`ctx` 始终第一位;查库走 `s.dbRepo.Default()` 或 `Get("xxx")`;写库走 `txManager.Execute`。
5. 错误:用 `errx.XXX().WithCode(...).WithMessage(...)`;`errx.Internal().WithCause(err)` 带底层 error;唯一冲突给稳定 `code`。
6. 响应:list 接口输出 `{list, meta}`,meta 由 `NewListMeta` 构造;时间字段用 `string`(`formatTime`)。
7. ID:沿用 `Base`,不在业务层生成。
8. 审计:确认路由在 `protected` 分组;需要落 `target_type/target_id/detail` 时调 `request.SetAuditMeta`。
9. 测试:`pkg/validation`、`pkg/errx`、`pkg/transaction` 等核心包已有单测,新加 service 至少一个 happy path 单元测试。
