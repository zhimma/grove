# 开发规范

## 目标

本项目用于接口开发，整体采用类似 Laravel 的目录约定和 CLI 体验，但代码风格遵循 Go 的直接表达，不引入 Repository、DDD、DTO/VO 等额外抽象。

## 分层

- `handler`
  - 只处理 HTTP：参数绑定、上下文提取、调用 service、输出响应
  - 自己定义 HTTP Request/Response
  - 简单的一层字段映射直接写在 handler 内，不额外拆 `toXxxDetail` 这类辅助函数
  - 不直接持有数据库连接，不直接查询 model
- `service`
  - 只接收 `context.Context`
  - 负责业务逻辑、事务、聚合、任务投递
  - 优先使用 `Input/Output` 结构体
- `model`
  - 放共享 GORM 模型和可复用查询辅助
  - 不做权限判断，不做 HTTP 响应拼装

## Monorepo

- 当前仓库采用单仓库模式：
  - Go 后端保留在仓库根级结构
  - 管理后台前端作为子仓目录维护在 `web/admin-vben`
- 当前已接入的前端包：
  - `web/admin-vben`
- 根目录统一使用：
  - `pnpm install:admin-vben`
  - `pnpm dev:admin`
  - `pnpm build:admin`

## 约束

- 新增管理后台模块优先使用 `go run ./cmd/grove make:module Name`
- 统一通过 `response.Success` / `response.Fail` 输出响应
- 请求上下文统一通过 `pkg/request` 读写
- JWT 认证统一通过 `app/api/middleware`
- 不在 handler 中 new 数据库或任务客户端
- 数据库通过 `provider.DB` 的命名资源访问，不把业务语义写死在数据库层
- Casbin 通过 `provider.GetEnforcer(name)` 注入，不在 handler 中自行初始化
- 运行时日志统一使用 `pkg/logger`，不要在业务代码中直接使用标准库 `log`
- 日志消息尽量使用中文；字段名保持英文 snake_case，便于机器检索
- CLI 的 `fmt.Print*` 仅用于命令行结果输出，不作为运行时日志

## 多数据库资源

- `databases.default` 仍是默认连接
- `databases.resources` 支持任意命名的额外数据库资源，例如 `orders`、`crm`、`analytics`
- 业务层需要指定资源时，通过 `provider.DB.Get("orders")` 取得对应连接
- 当前只解决“多数据库资源管理”，不在框架层预设读写分离或区域路由

## Casbin

- `casbin.enforcers` 支持定义任意命名执行器
- 每个执行器可以绑定独立数据库资源和独立规则表
- 默认支持两种模型：
  - `rbac`
  - `rbac_domains`
- API 层可通过权限中间件挂载到具体路由组

## 管理后台

- 管理后台应用放在 `app/console`
- 管理后台前端放在 `web/admin-vben`
- 管理后台前后端采用同仓维护，不单独拆仓
- 当前已接入的核心能力：
  - 管理员登录 / 刷新 / 登出
  - 当前管理员信息 / 修改密码 / 更新个人资料
  - Dashboard summary
  - 角色列表、详情、创建、更新、删除
  - 角色 API 权限分配
  - 角色菜单权限分配
  - 管理员列表、详情、创建、更新、状态变更、重置密码、删除
  - 系统配置
  - 文件上传
  - 登录日志 / 操作日志
- `web/admin-vben/apps/console` 当前保留的模板页面：
  - 登录
  - 工作台
  - 系统配置
  - 管理员管理
  - 角色权限
- 管理后台身份通过 token 验证后，按请求回库恢复授权态，并写入 `request.Identity`
- 管理后台 API 权限统一通过 `console` Casbin enforcer 校验
- 管理员与角色的 Casbin `g` 关系由 `AdminService` 在创建、换角色、删除时同步维护
- `console` 当前权限模型约束：
  - API 权限标识统一为 `METHOD + path`
  - API 权限清单来自运行时受保护路由
  - 菜单真相源是前端本地路由
  - 后端只代存储 `console_roles.menu_keys`
