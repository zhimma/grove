# Grove 当前状态与下一步

本文汇总当前开发进度和验收边界；不作为发布成功证明。功能行为以源码、配置和对应指南为准，逐项工作记录见[升级清单](plans/2026-08-29-grove-framework-upgrade-plan.md)。

## 当前结论

Grove 以完整 fork / clone 的方式复用，定位是 console-first Go 单体脚手架。主要前后端改造、结构收敛和 Go 工具链升级已落地，已完成本机数据库/Redis及关键页面验收，仍有发布环境验收与真实业务接入工作，不能标记为“所有工作完成”或“生产已验证”。

| 范围 | 当前状态 | 事实入口 |
| --- | --- | --- |
| 框架结构与开发风格 | 三入口单体、显式装配、精确依赖；服务专属代码位于各自 `internal/` | [架构](architecture.md)、[项目结构](guide/structure.md) |
| 后台基础能力 | 认证、会话、RBAC、用户与配置管理、上传、审计、计划任务管理已接入 | [Console 架构与权限](02-console-架构与权限.md)、[计划任务](guide/scheduler.md) |
| 常用组件 | 日志轮转、验证、统一响应、分页、缓存、事件、队列、存储等已有实现 | [基础组件](guide/pkg-components.md)、[统一响应](04-响应与错误处理规范.md) |
| 模块生成 | 生成双方言迁移、后端 CRUD/测试/OpenAPI，并在存在前端契约文件时生成 API、页面和路由 | [新增模块指南](03-console-新增模块指南.md)、[生成器](../cmd/grove/) |
| 测试夹具 | `OpenDB` 与 `CreateCasbinTable` 已共用；没有通用模型工厂和 HTTP 测试助手 | [测试策略](development/testing.md)、[testkit 源码](../internal/testkit/testkit.go) |
| 工具链 | Go 1.27.1，golangci-lint v2.14.0；本地、CI 与 Docker 构建配置已对齐 | [go.mod](../go.mod)、[mise](../.mise.toml)、[Makefile](../Makefile) |

## 待完成与暂缓

| 类型 | 事项 | 完成条件 |
| --- | --- | --- |
| 已修正 | MySQL CI 与就绪等待 | CI 无 Docker 时明确失败；真实 SQL 就绪后执行。两种数据库生命周期与安全回滚均在 OrbStack 实测通过 |
| 本地已验收 | 本机基础设施与镜像 | Compose、PostgreSQL/MySQL/Redis 已实测；三个最终服务镜像 readiness、非 root、只读根文件系统及优雅退出均通过 |
| 部分验收 | 浏览器、认证权限、上传、计划任务、优雅退出 | 登录、页面、配置保存和手动任务已在本机通过；最小权限角色、上传下载及完整发布环境仍按 [Staging 清单](deployment/staging-checklist.md)执行 |
| 待验证 | 真实业务模块接入（旧 T9） | 在实际项目中从生成到浏览器验收，并记录需要手改的位置；自动生成 Invoice 的测试不能替代此项 |
| 暂缓 | 邮件（T6/G9）、通知（T7）、通用接口限流（G8） | 明确实际发送场景、通知渠道或正式 API 配额策略后，再制定实现与验收任务；当前只有登录保护 |
| 暂缓 | 模型工厂、HTTP 测试助手（旧 T8 的剩余范围） | 出现值得共用的重复场景后再抽取；现有数据库夹具已完成 |

多实例部署还受现有约束限制：Casbin 策略周期重载存在传播延迟；Scheduler 的共享锁有 TTL，释放并非原子比较删除，互斥不等于同一调度只执行一次。详见[权限](guide/permission.md)和[计划任务](guide/scheduler.md)，不要仅凭组件存在就承诺任意多副本可靠性。

## 下一步顺序

1. 完成多 Worker/队列、最小权限角色、令牌刷新、上传下载等剩余 Staging 验收及镜像漏洞扫描。
2. 在真实项目中记录一个业务模块从生成到交付的接入结果。
3. 提交、推送须按用户授权执行；以对应提交的远端 CI 和制品记录作为交付证据。

每次勾选升级任务时，同步填写实现范围和验证证据；暂缓项保持明确标识，历史测试结果不改写为本次验证结果。
