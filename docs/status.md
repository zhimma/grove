# 项目范围与后续方向

Grove 是通过整仓 fork / clone 复用的 Go 单体脚手架。当前重点是后台基础能力与新增业务模块的开发体验，不对外提供独立组件版本或自动升级通道。

## 已有边界

- Console 提供管理员、终端用户、角色、会话、配置、上传、审计和计划任务管理；文章、API starter 和 echo 队列任务是可裁剪示例。
- API、Console、Worker 分别启动，共享内部模型与基础组件；跨服务调用不会绕过各自认证和授权。
- 支持 PostgreSQL/MySQL 迁移，以及本地/Redis 缓存、Asynq 队列、进程内事件和 Local/S3 存储。
- 生成器覆盖基础 CRUD 前后端代码和契约登记；业务规则、真实数据库和页面验收由项目补齐。

## 使用前需要理解

| 能力 | 约束 |
| --- | --- |
| Casbin 策略 | 跨实例依赖周期重载，存在传播延迟 |
| Scheduler | 共享锁有 TTL，不自动续期，释放不是原子比较删除；不承诺每次调度恰好执行一次，任务必须幂等 |
| 任务管理 | 任务体在代码注册，后台只调整调度；仅保存上次执行摘要 |
| Event | 仅进程内分发，不是持久消息队列 |
| 测试夹具 | SQLite 测试不替代真实 PostgreSQL/MySQL 生命周期测试 |
| 部署 | CI 与本地测试不替代目标环境的浏览器、代理、存储和故障恢复验收 |

详细边界分别见[权限](02-console-架构与权限.md)、[计划任务](guide/scheduler.md)、[测试](development/testing.md)和[发布清单](deployment/staging-checklist.md)。

## 后续方向

优先用真实业务模块验证生成器与公共组件，减少接入时重复编写的代码；完善多实例任务、队列及浏览器的持续验证。

邮件、通知、通用接口配额、模型工厂和 HTTP 测试助手尚未提供，出现明确共用场景后再实现。多租户、插件系统、工作流、服务容器和通用 Repository 不属于当前基础范围。
